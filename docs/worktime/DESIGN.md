# 위례 근태·초과근무 관리 Tool — 설계서

> 선택적 근로시간제의 **30% 필수 8시간 인원**을 Teams + 엑셀 수기로 맞추던 작업을 대체하는 도구.
> 규칙 명세 · 판정 엔진 · 구현 결정 · 미결정 사항을 한 곳에 모았다.
>
> 구현: [`../../worktime/index.html`](../../worktime/index.html) (단일 파일) ·
> 사용법: [`../../worktime/README.md`](../../worktime/README.md)

## 1. 목표 (한 줄)

**근태 입력 → 날짜별 30% 인원 충족 여부 즉시 판정 + 미달일 조율 후보 제시 + 개인 총량·OT 잔여 관리.**

## 2. 현행 운영 (As-Is)

- 위례사업소는 **선택적 근로시간제** 시행 — 월 총량(예: 160시간) 안에서 각자 다음 달 근로계획을
  전월 말에 수립해 파트장·팀장 사전 승인
- 3개 그룹(A·B·C)으로 나눠 **Teams에 엑셀 파일**을 두고, 8시간을 채우지 못하는 인원이
  월달력에 날짜별 사유(출장·교육·8시간 미만·휴가·건강검진 …)를 **각자 수기 기입**
- 그 엑셀을 보고 30%가 안 차면 구성원끼리 조율해 8시간 인원을 채움

**병목**: 채우지 못하는 사람만 적는 방식은 맞지만, ① 30% 충족 여부를 사람이 세야 하고
② 어떤 근무 조합이 규칙에 맞는지(코어타임·반차 배치)는 표에 드러나지 않고
③ 조율 대상을 찾으려면 표를 눈으로 훑어야 한다. 이 세 가지가 자동화 대상이다.

## 3. 조직 · 인원

| 그룹 | 구성 | 인원 |
|---|---|---|
| **A** 직책자 | 김동환(발전운영팀장) · 고재민(정비기술팀장) · 임태균(발전지원) · 정병철(기계) · 민준홍(전기) · 한승백(제어) | 6 |
| **B** 구성원 | 기계 5 · 전기 3 · 제어 2 · 정비지원 5 | 15 |
| **C** 구성원 | 발전지원 3 | 3 |
| | **합계** | **24** |

- 윤승현(정비지원) **육아휴직** → 30% 모수에서 제외 → 활성 **23명**
- 30% 필수 8시간 인원 = ⌈23 × 0.3⌉ = **7명**
- 정비지원파트는 파트장이 없다

### 그룹으로 묶는 이유

파트별로 30%를 적용하면 4명 파트 → ⌈1.2⌉ = 2명, 5명 파트 → ⌈1.5⌉ = 2명이 되어
올림 손실(0.8 + 0.5 …)이 누적된다. 그룹 단위로 묶으면 그 마진이 살아난다.
**30% 판정은 두 팀 합산 기준**이고, A·B·C 그룹은 관리·입력 단위다.

## 4. 규칙 명세

### 4.1 선택적 근로시간제

| 항목 | 값 |
|---|---|
| 정규 근로시간 | 08:30~17:30 (점심 휴게 12:00~13:00 제외 8시간) |
| **코어타임** | 08:30~11:30 (3시간) — 근로하거나 반차·반반차·연차로 덮여야 함 |
| 선택근로 사용 범위 | 07:30~20:30 (정규 앞 1시간 · 뒤 3시간) |
| 1일 인정 상한 | 11.5시간 (13시간 − 점심 1시간 − 석식 30분) |
| 최소 사용 단위 | 30분 |
| 1일 최소 근로 | 3시간 — 더 줄이려면 당일 연차 |
| 월 총량 | 소정근로일 × 8시간 (2026-09 = 20일 × 8 = **160시간**) |

**석식 휴게 17:30~18:00은 실시한 경우에만 공제한다.** 근거: `08:00~18:00`을 "9시간(저녁 휴게시간
없이)"으로, `07:30~20:30`을 "11시간 30분"으로 계산하는 것은 이 해석으로만 둘 다 성립한다.
도구의 자동 판정은 18:00 이후까지 근무한 경우를 실시로 본다(§11-2 확인 필요).

### 4.2 8시간 인정과 30% 룰

- 8시간 인정 = **사내 실근로 8시간 이상** — `07:30~16:30` · `08:00~17:00` · `08:30~17:30`
- **출장 · 교육 · 건강검진 · 반차 · 반반차 · 연차는 시간과 무관하게 미충족**
  (4시간 근로 + 4시간 출장도 미충족 — 회사 내 8시간이 기준)
- 필수 인원 = 모수 × 30% **올림** — 30명 → 9 · 25명 → 7.5 → 8 · 23명 → 6.9 → 7
- **직책자(팀장·파트장) 중 1명 이상**이 8시간에 포함
- **파트당 2명** (구성원 3명 이하 파트는 1명) — 그룹 운영 + **팀장 승인 시 유예 가능**
  → 도구는 **경고로만** 표시하고 충족 판정을 막지 않는다
- 30% 자체도 적합한 사유가 있으면 팀장 재량으로 미달 승인 가능 → 도구는 미달일을 표시하되
  차단하지 않는다

### 4.3 반차 · 반반차

반차 4시간, 반반차 2시간. 전달받은 가능/불가능 사례는 다음과 같다.

| 조합 | 가부 | 사유 |
|---|---|---|
| 오전 반차 08:00~13:00 + 근무 13:00~17:00 | ○ | |
| 오전 반차 08:30~13:30 + 근무 13:30~17:30 | ○ | |
| 오전 반차 09:00~14:00 | ✗ | 코어타임 위반 |
| 오전 반차 07:30~12:30 | ✗ | 휴게시간 중합 |
| 근무 07:30~12:00 + 오후 반차 12:00~17:00 | ○ | |
| 근무 08:00~12:00 + 오후 반차 12:00~17:00 | ○ | |
| 근무 08:30~13:30 + 오후 반차 13:30~17:30 | ○ | |
| 근무 08:30~14:00 + 오후 반차 14:00~18:00 | ○ | |
| 오전 반반차 08:30~10:30 | ○ | 정규 근로시간 앞 |
| 오후 반반차 15:30~17:30 | ○ | 정규 근로시간 뒤 |

반차·반반차 사용 시 **30% 인원에는 포함되지 않는다.** 건강검진은 반차 4시간으로 인정한다.

### 4.4 OT (초과근로)

- 본인이 실적을 직접 기입 · 월 한도가 있어 **누적과 잔여를 자동 계산**
- 월 한도 기본값 20시간 — **사규 확인 필요**(§11-3)

### 4.5 탄력적 근로시간제

- 대정비(MI · HGPI · CI) 달은 OT가 많아 **3개월 단위기간**으로 관리
  (9월 대정비 → 9·10·11월)
- **단위기간 평균 주 52시간 이하** · **개별 주 64시간 이하**
- 단위기간에는 **선택적 근로를 사용할 수 없고**, 일정한 정규 근로시간(예 08:00~17:00) +
  OT로 운영 (07:00~08:00, 17:00~18:00 등)

## 5. 도출한 일반 규칙 — 이 프로젝트의 핵심

§4.3 의 가능/불가능 사례는 목록으로 하드코딩할 수도 있지만, 그렇게 하면 목록에 없는 조합을
판정할 수 없다. 네 개의 불가·가능 경계를 모두 재현하는 **두 개의 일반 규칙**을 도출했다.

```
규칙 A — 휴가 블록의 순 시간
  블록 순시간 = 블록 clock 시간 − 블록에 완전히 포함된 점심 휴게(1h)
  이 값이 정확히 4시간(반차) / 2시간(반반차)이어야 한다.
  점심 휴게와 "일부만" 겹치면 불가 = 휴게시간 중합.
     07:30~12:30 → clock 5h, 점심과 30분만 겹침 → 순 4.5h ≠ 4h  ✗
     08:00~13:00 → clock 5h, 점심 1h 완전 포함  → 순 4h        ○
  ※ 석식 휴게는 휴가 블록에 적용하지 않는다 — 14:00~18:00 반차가 4시간으로
     성립하는 것이 그 근거다(그 시간대에 쉬는 사람에게는 석식 휴게가 발생하지 않는다).

규칙 B — 코어타임 완전 피복
  근무 구간 ∪ 휴가 블록 이 08:30~11:30 전체를 덮어야 한다.
     09:00~14:00 반차 → 08:30~09:00 이 어느 쪽에도 안 덮임 → ✗ (코어타임 위반)
     08:00~11:00 근무 → 11:00~11:30 이 비어 있음          → ✗ (3시간이지만 불가)
```

두 규칙만으로 §4.3 표 전체와, 별도로 전달받은 `08:30~11:30 ○` / `08:00~11:00 ✗` 까지
전부 재현된다. 반차 블록은 사용자가 입력하지 않고 **근무 시각에서 역산**한다
(오전 반차는 근무 시작에서 뒤로, 오후 반차는 근무 종료에서 앞으로).

## 6. 판정 엔진

```
[입력] 유형 · 근무 시작·종료 · 석식 실시 여부 · OT · 사유
   │
   ▼ 휴가 블록 역산 (규칙 A)          ← 반차 · 반반차 · 건강검진
[근무 구간 + 휴가 블록]
   │
   ▼ 실근로 = clock − 점심 − (석식 실시 시 30분)
   ▼ 규칙 검사 — 코어타임 피복(규칙 B) · 30분 단위 · 사용 범위 ·
                 최소 3시간 · 상한 11.5시간 · 휴게 중합
[일별 결과] 실근로h · 총량 인정h · 30% 충족 · 위반 목록
   │
   ├─▶ 날짜별 집계 → 필요 인원 ⌈모수×0.3⌉ 대조 · 직책자 · 파트
   │                → 미달일 + 조율 후보 (조율 가능한 사유만)
   ├─▶ 개인 월 집계 → 총량 대비 적립/부족 · OT 누적/잔여
   └─▶ 탄력 단위기간 → 주별 합계 · 평균 주 52h · 개별 주 64h
```

**조율 후보**는 그 날 8시간 미충족인 사람 중 **바꿀 수 있는 사유**(선택근로 8시간 미만 ·
반차 · 반반차)만 뽑는다. 출장 · 교육 · 연차 · 건강검진은 조율 대상이 아니므로 제외한다.

## 7. 구현 결정 — 왜 단일 HTML 파일인가

| 후보 | 장점 | 문제 |
|---|---|---|
| 엑셀 강화 (수식·매크로) | Teams 공동편집 유지 · 익숙함 | 코어타임 피복, 휴가 블록 역산 같은 규칙을 수식으로 표현하면 유지보수 불가 |
| 파이썬 데스크톱 앱 | 강력 · 기존 `tool/` 과 일관 | 24명 PC 배포·업데이트 부담. 구성원이 매일 쓰기엔 무겁다 |
| 서버 웹앱 | 실시간 공유 | 사내 인프라·보안 승인 필요 |
| **단일 HTML 파일** ✅ | 설치·로그인·인터넷 불필요, 파일 하나 전달, 규칙을 코드로 관리, 브라우저 자동 저장 | 동시 편집 불가 → JSON 합치기 / CSV 로 취합 |

"단순하고 직관적"이라는 요구에는 **더블클릭하면 열리는 파일 하나**가 가장 가깝다.
기준값은 코드가 아니라 설정 화면에 있어, 규칙이 바뀌면 설정만 고친다.

## 8. 검증

전달받은 운영 사례를 **가능·불가능 양쪽 모두** 회귀 케이스로 고정했다. 도구의
「규칙 · 검증기」 탭에서 언제든 실행할 수 있고, 기준값을 바꾼 뒤 여기가 전부 통과하는지로
의도한 변경인지 확인한다.

- 근무 조합 22건 (실근로 시간 · 사용 가부 · 30% 충족 · 휴가 블록 위치)
- 30% 필수 인원 올림 5건 (30 → 9 · 25 → 8 · 23 → 7 · 17 → 6 · 16 → 5)
- 총 **68개 단정** 전부 일치

## 12. 추가 제안

1. **승인 상태 관리** — 전월 말 계획에 대한 파트장·팀장 승인 여부를 기록해, 승인 없이 확정된
   계획을 구분한다. 30% 미달을 팀장 재량으로 승인한 날도 근거로 남는다.
2. **계획 / 실적 2계층** — 지금은 한 계층이다. 사전 승인받은 계획과 실제 실적을 나누면
   차이가 큰 날을 찾을 수 있다.
3. **8시간 부담 형평성** — 누가 월에 몇 일 8시간을 맡았는지 집계. 조율할 때 형평성 근거가 된다.
4. **선택근로 기간의 주 52시간 사전 경고** — 지금은 탄력 기간에만 판정한다. 선택근로에서도
   OT를 몰아 쓰면 주 단위 한도에 걸릴 수 있다.
5. **연차 잔여 연동** — 반차·반반차·연차 사용분을 합산해 잔여 연차를 함께 보여준다.
