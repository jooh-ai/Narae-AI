# 위례 근태·초과근무 관리 Tool — 설계서

> 선택적 근로시간제의 **30% 필수 8시간 인원**을 Teams + 엑셀 수기로 맞추던 작업을 대체하는 도구.
> 규칙 명세 · 판정 엔진 · 구현 결정 · 미결정 사항을 한 곳에 모았다.
>
> 구현: [`../../worktime/index.html`](../../worktime/index.html) (단일 파일) ·
> 사용법: [`../../worktime/README.md`](../../worktime/README.md)

## 1. 목표 (한 줄)

**근태 입력 → 날짜별 30% 인원 충족 여부 즉시 판정 + 미달일 조율 후보 제시 + 개인 총량·OT 잔여 관리.**

## 2. 현행 운영 (As-Is)

- 위례사업소는 **선택적 근로시간제** 시행 — 월 총량(예: 160시간) 안에서 각자 다음 달 근로계획을
  전월 말에 수립해 파트장·팀장 사전 승인
- 3개 그룹(A·B·C)으로 나눠 **Teams에 엑셀 파일**을 두고, 8시간을 채우지 못하는 인원이
  월달력에 날짜별 사유(출장·교육·8시간 미만·휴가·건강검진 …)를 **각자 수기 기입**
- 그 엑셀을 보고 30%가 안 차면 구성원끼리 조율해 8시간 인원을 채움

**병목**: 채우지 못하는 사람만 적는 방식은 맞지만, ① 30% 충족 여부를 사람이 세야 하고
② 어떤 근무 조합이 규칙에 맞는지(코어타임·반차 배치)는 표에 드러나지 않고
③ 조율 대상을 찾으려면 표를 눈으로 훑어야 한다. 이 세 가지가 자동화 대상이다.

## 3. 조직 · 인원

| 그룹 | 구성 | 인원 |
|---|---|---|
| **A** 직책자 | 김동환(발전운영팀장) · 고재민(정비기술팀장) · 임태균(발전지원) · 정병철(기계) · 민준홍(전기) · 한승백(제어) | 6 |
| **B** 구성원 | 기계 5 · 전기 3 · 제어 2 · 정비지원 5 | 15 |
| **C** 구성원 | 발전지원 3 | 3 |
| | **합계** | **24** |

- 윤승현(정비지원) **육아휴직** → 30% 모수에서 제외 → 활성 **23명**
- 30% 필수 8시간 인원 = ⌈23 × 0.3⌉ = **7명**
- 정비지원파트는 파트장이 없다

### 그룹으로 묶는 이유

파트별로 30%를 적용하면 4명 파트 → ⌈1.2⌉ = 2명, 5명 파트 → ⌈1.5⌉ = 2명이 되어
올림 손실(0.8 + 0.5 …)이 누적된다. 그룹 단위로 묶으면 그 마진이 살아난다.
**30% 판정은 두 팀 합산 기준**이고, A·B·C 그룹은 관리·입력 단위다.

## 4. 규칙 명세

### 4.1 선택적 근로시간제

| 항목 | 값 |
|---|---|
| 정규 근로시간 | 08:30~17:30 (점심 휴게 12:00~13:00 제외 8시간) |
| **코어타임** | 08:30~11:30 (3시간) — 근로하거나 반차·반반차·연차로 덮여야 함 |
| 선택근로 사용 범위 | 07:30~20:30 (정규 앞 1시간 · 뒤 3시간) |
| 1일 인정 상한 | 11.5시간 (13시간 − 점심 1시간 − 석식 30분) |
| 최소 사용 단위 | 30분 |
| 1일 최소 근로 | 3시간 — 더 줄이려면 당일 연차 |
| 월 총량 | 소정근로일 × 8시간 (2026-09 = 20일 × 8 = **160시간**) |

**석식 휴게는 정규 근로 종료 직후 30분이고, 실시한 경우에만 공제한다.** 선택근로는
`17:30~18:00`, 탄력근무 `08:00~17:00`이면 `17:00~17:30`. 근무와 OT 모두 실시 여부를
입력자가 고른다 — 탄력근무 OT `17:00~20:00`은 미실시 3시간 / 실시 2.5시간.
자동 판정은 석식 창 종료 이후까지 이어진 경우를 실시로 본다.

**휴가를 쓰면 그만큼 월 총량이 줄어든다.** 소정 160시간인 달에 연차 1일을 쓰면 조정 총량은
152시간이 되고, 실근로 합계를 그 값과 비교한다.

### 4.2 8시간 인정과 30% 룰

- 8시간 인정 = **사내 실근로 8시간 이상** — `07:30~16:30` · `08:00~17:00` · `08:30~17:30`
- **출장 · 교육 · 건강검진 · 반차 · 반반차 · 연차는 시간과 무관하게 미충족**
  (4시간 근로 + 4시간 출장도 미충족 — 회사 내 8시간이 기준)
- 필수 인원 = 모수 × 30% **올림** — 30명 → 9 · 25명 → 7.5 → 8 · 23명 → 6.9 → 7
- **판정은 두 팀 전체 합산** (사규상 확인 완료) — 팀장 2명도 모수에 포함
- **직책자(팀장·파트장) 중 1명 이상**이 8시간에 포함
- **파트당 2명** (구성원 3명 이하 파트는 1명) — 그룹 운영 + **팀장 승인 시 유예 가능**
  → 도구는 **경고로만** 표시하고 충족 판정을 막지 않는다
- 30% 자체도 적합한 사유가 있으면 팀장 재량으로 미달 승인 가능 → 도구는 미달일을 표시하되
  차단하지 않는다

### 4.3 반차 · 반반차

반차 4시간, 반반차 2시간. 전달받은 가능/불가능 사례는 다음과 같다.

| 조합 | 가부 | 사유 |
|---|---|---|
| 오전 반차 08:00~13:00 + 근무 13:00~17:00 | ○ | |
| 오전 반차 08:30~13:30 + 근무 13:30~17:30 | ○ | |
| 오전 반차 09:00~14:00 | ✗ | 코어타임 위반 |
| 오전 반차 07:30~12:30 | ✗ | 휴게시간 중합 |
| 근무 07:30~12:00 + 오후 반차 12:00~17:00 | ○ | |
| 근무 08:00~12:00 + 오후 반차 12:00~17:00 | ○ | |
| 근무 08:30~13:30 + 오후 반차 13:30~17:30 | ○ | |
| 근무 08:30~14:00 + 오후 반차 14:00~18:00 | ○ | |
| 오전 반반차 08:30~10:30 | ○ | 정규 근로시간 앞 |
| 오후 반반차 15:30~17:30 | ○ | 정규 근로시간 뒤 |

반차·반반차 사용 시 **30% 인원에는 포함되지 않는다.** 건강검진은 반차 4시간으로 인정한다.

### 4.4 OT (초과근로)

- 본인이 실적을 직접 기입 · 월 한도가 있어 **누적과 잔여를 자동 계산**
- 선택적 근로는 30분 단위지만 **OT 는 분 단위**로 신청 → 시작·종료 시각을 받아 자동 계산
- **월 한도 = 그 달 기본 가능시간 + 휴가 사용시간** — 1일 휴가(8시간)를 쓰면 OT 가능시간이
  8시간 늘어난다. 기본 가능시간은 달마다 다르므로(2026-04 = 56시간) 월별로 입력받는다.
  기본 가능시간의 산정 규칙은 담당자 확인 필요(§11-3)
- **자정을 넘는 OT** 가능 — 24시간 어느 때나. 야간(22:00~06:00) 가산은 급여 시스템 소관이고
  이 도구는 근로시간만 관리한다
- 주말·공휴일 근무도 입력할 수 있고 **휴일 가산 없이 근로시간만** 계산한다.
  휴일에는 코어타임·최소 근로·사용 범위 규칙을 적용하지 않는다
- 선택근로 시간과 OT 시간은 **나눠서 입력**한다 — 근거는 §5-1

### 4.5 탄력적 근로시간제

- 대정비(MI · HGPI · CI) 달은 OT가 많아 **3개월 단위기간**으로 관리
  (9월 대정비 → 9·10·11월)
- **단위기간 평균 주 52시간 이하** · **개별 주 64시간 이하**
- 단위기간에는 **선택적 근로를 사용할 수 없고**, 일정한 정규 근로시간(예 08:00~17:00) +
  OT로 운영 (07:00~08:00, 17:00~18:00 등)

## 5. 도출한 일반 규칙 — 이 프로젝트의 핵심

§4.3 의 가능/불가능 사례는 목록으로 하드코딩할 수도 있지만, 그렇게 하면 목록에 없는 조합을
판정할 수 없다. 경계를 모두 재현하는 **일반 규칙**을 도출했다.

```
규칙 A — 휴가 블록의 순 시간
  블록 순시간 = 블록 clock 시간 − 블록에 완전히 포함된 점심 휴게(1h)
  이 값이 정확히 4시간(반차) / 2시간(반반차)이어야 한다.
  점심 휴게와 "일부만" 겹치면 불가 = 휴게시간 중합.
     07:30~12:30 → clock 5h, 점심과 30분만 겹침 → 순 4.5h  ✗
     08:00~13:00 → clock 5h, 점심 1h 완전 포함  → 순 4h    ○
  ※ 석식 휴게는 휴가 블록에 적용하지 않는다 — 14:00~18:00 반차가 4시간으로
     성립하는 것이 그 근거다(그 시간대에 쉬는 사람에게는 석식 휴게가 발생하지 않는다).

규칙 B — 코어타임 완전 피복
  근무 구간 ∪ 휴가 블록 이 08:30~11:30 전체를 덮어야 한다.
     09:00~14:00 반차 → 08:30~09:00 이 어느 쪽에도 안 덮임 → ✗
     08:00~11:00 근무 → 11:00~11:30 이 비어 있음          → ✗ (3시간이지만 불가)

규칙 C — 휴가 블록의 배치 가능 영역
  블록은 선택근로 사용 범위(07:30~20:30) 안에 있어야 하고,
  코어타임을 나눌 수 없다 — 양 끝이 코어타임 "중간"에 올 수 없다.
     08:30~17:30 근무 + 오전 반차 → 블록 04:30~08:30 → 범위 밖         ✗
     08:30~17:30 근무 + 오후 반차 → 블록 17:30~21:30 → 범위 밖         ✗
     07:30~10:30 근무 + 오후 반차 → 블록 10:30~15:30 → 코어 중간 시작  ✗
  ※ 반반차(2h)는 3시간 코어타임을 필연적으로 나누므로 이 규칙에서 제외하고,
     대신 정규 근로시간 앞뒤 고정 위치(08:30~10:30 · 15:30~17:30)로 제한한다.

규칙 D — 휴게시간 경계
  근무 시작·종료가 휴게시간 중간일 수 없다.
     08:00~12:30 퇴근은 08:00~13:00 과 인정시간이 같아 의미가 없다.  ✗
  규칙 A 의 "휴게를 쪼개지 않는다"를 근무 구간에도 적용한 것. (§11-8 확인 필요)

규칙 E — 반차 사용일의 인정시간 한도
  반차·반반차는 그날 8시간을 채우지 못할 때 쓰는 것이므로,
  하루 인정시간(근로 + 휴가)이 8.5시간을 넘을 수 없다.
     07:30~16:00 근무(7.5h) + 오후 반차(4h) = 11.5h  ✗
  8시간 인정(30% 인원)은 순수 근무로만 성립한다 — 휴가를 끼워 8시간을 만들 수 없다.

규칙 F — 반차는 점심 시간대까지
  오전 반차는 점심 휴게까지 이어져야 하고, 오후 반차는 점심 휴게 이후부터 시작한다.
     07:30~11:30 오전 반차 → 점심에 못 미침                      ✗
     08:00~13:00 / 08:30~13:30 오전 반차 → 13:00 / 13:30 출근    ○
  "오전 반차(08~12시)를 쓰면 13시에 들어온다"가 이 규칙의 실무 표현이다.

규칙 G — 휴게시간에는 근무를 시작할 수 없다
  휴게시간은 근무로 인정하지 않으므로 그 안에서 시작하거나 끝날 수 없다.
     12:00 / 12:30 출근  ✗ (오전 반차 뒤에는 13:00 출근)
     08:00~12:30 퇴근    ✗
```

휴가 블록은 사용자가 입력하지 않고 **근무 시각에서 역산**한다
(오전 반차는 근무 시작에서 뒤로, 오후 반차는 근무 종료에서 앞으로).

### 규칙이 만들어내는 사용 가능 조합

규칙을 30분 격자 전체에 돌려 나온 결과 — 목록이 아니라 규칙이 이 범위를 만든다.

| 유형 | 가능한 조합 | 형태 |
|---|---|---|
| 선택근로 | 54건 | 시작 07:30 · 08:00 · 08:30 / 종료 11:30 이후 (12:30 제외) · 8시간 이상이면 30% 충족 |
| 오전 반차 | 9건 | 블록 **08:00~13:00 · 08:30~13:30** 두 가지 — 근무는 13:00 / 13:30 시작 |
| 오후 반차 | 9건 | 근무 시작 07:30 · 08:00 · 08:30 / 블록은 점심 이후 시작 |
| 오전 반반차 | 9건 | 블록 08:30~10:30 고정, 근무 10:30 시작 |
| 오후 반반차 | 2건 | 블록 15:30~17:30 고정, 근무 15:30 종료 |

규칙 E·F·G 를 넣기 전에는 각각 54 · 40 · 29 · 13 · 3 건이었다. 성립하지 않는 조합이
그만큼 열려 있었다는 뜻이다.

## 5-1. OT 입력 방식 — 왜 분리 입력인가

선택적 근로는 30분 단위지만 **OT 는 분 단위**로 신청하므로, OT 는 시작·종료 시각을 받아
자동 계산한다(`18:00~19:45` → 1.75시간).

문제는 사람들이 `07:30~20:30` 선택근로 뒤에 `20:30~22:30` OT 를 한 경우
**출퇴근을 `07:30~22:30` 하나로 적는다**는 것이다. 두 방식을 비교했다.

| 방식 | 문제 |
|---|---|
| 총 근무 시각 하나 + OT 시간 수기 | `07:30~22:30, OT 2h` 로 적으면 소정이 자동으로 13.5 − 2 = 11.5h 가 되어 **상한과 우연히 같아지고 오입력이 검증되지 않는다.** OT 를 빠뜨리면 13.5h 상한 위반만 뜨고 왜 틀렸는지 알 수 없다 |
| **선택근로 시각 + OT 시각 분리** ✅ | 각각 독립 검증 — 선택근로 11.5h 상한 · OT 한도 · 두 구간 겹침을 따로 잡는다. 승인 절차와 법적 성격이 다른 두 시간을 섞지 않는다 |

분리 입력을 기본으로 하되, 합쳐 적는 습관을 막기 위해 두 장치를 넣었다.

- 근무 종료를 `20:30` 넘게 넣으면 **"20:30 이후 N시간을 OT 로 분리"** 버튼이 나타난다
  (누르면 근무 `07:30~20:30` + OT `20:30~22:30` 으로 쪼개진다)
- OT 시각이 근무 시각과 겹치면 경고한다

## 5-2. 30% 판정 단위 — 그룹화가 실제로 유리한가

그룹화의 원래 목적은 파트별 올림 손실을 줄이는 것이었다. 세 방식을 실제로 계산했다
(활성 23명 기준, 도구의 「판정 단위 비교」 KPI 가 이 값을 보여준다).

| 판정 단위 | 계산 | 필요 인원 |
|---|---|---|
| **전체 합산 (두 팀)** | ⌈23 × 0.3⌉ | **7명** |
| 그룹별 (A·B·C) | ⌈6×.3⌉ + ⌈14×.3⌉ + ⌈3×.3⌉ = 2 + 5 + 1 | 8명 |
| 파트별 | 팀장 1 + 발전지원 2 + 기계 2 + 전기 2 + 제어 1 + 정비지원 2 | 10명 |

**올림은 한 번만 할수록 유리하다.** 그룹화는 파트별(10명)보다는 낫지만 전체 합산(7명)보다
1명 불리한 **중간 단계**였다. 전체 합산으로 판정할 수 있다면 그룹은 **판정 단위로는 불필요**하고,
**입력·관리 단위**(누가 어느 시트를 보고 누가 조율하나)로만 의미가 있다.

도구는 그룹을 **보기 필터**로만 쓰고 판정은 전체 합산으로 한다. 설정에서 `그룹별`로 바꿔
비교할 수 있다. 다만 사규·노사합의상 전체 합산 판정이 가능한지는 확인이 필요하다(§11-12).

## 6. 판정 엔진

```
[입력] 유형 · 근무 시작·종료 · 석식 실시 여부 · OT · 사유
   │
   ▼ 휴가 블록 역산 (규칙 A)          ← 반차 · 반반차 · 건강검진
[근무 구간 + 휴가 블록]
   │
   ▼ 실근로 = clock − 점심 − (석식 실시 시 30분)
   ▼ 규칙 검사 — 코어타임 피복(규칙 B) · 30분 단위 · 사용 범위 ·
                 최소 3시간 · 상한 11.5시간 · 휴게 중합
[일별 결과] 실근로h · 총량 인정h · 30% 충족 · 위반 목록
   │
   ├─▶ 날짜별 집계 → 필요 인원 ⌈모수×0.3⌉ 대조 · 직책자 · 파트
   │                → 미달일 + 조율 후보 (조율 가능한 사유만)
   ├─▶ 개인 월 집계 → 총량 대비 적립/부족 · OT 누적/잔여
   └─▶ 탄력 단위기간 → 주별 합계 · 평균 주 52h · 개별 주 64h
```

**조율 후보**는 그 날 8시간 미충족인 사람 중 **바꿀 수 있는 사유**(선택근로 8시간 미만 ·
반차 · 반반차)만 뽑는다. 출장 · 교육 · 연차 · 건강검진은 조율 대상이 아니므로 제외한다.

## 7. 구현 결정 — 왜 단일 HTML 파일인가

| 후보 | 장점 | 문제 |
|---|---|---|
| 엑셀 강화 (수식·매크로) | Teams 공동편집 유지 · 익숙함 | 코어타임 피복, 휴가 블록 역산 같은 규칙을 수식으로 표현하면 유지보수 불가 |
| 파이썬 데스크톱 앱 | 강력 · 기존 `tool/` 과 일관 | 24명 PC 배포·업데이트 부담. 구성원이 매일 쓰기엔 무겁다 |
| 서버 웹앱 | 실시간 공유 | 사내 인프라·보안 승인 필요 |
| **단일 HTML 파일** ✅ | 설치·로그인·인터넷 불필요, 파일 하나 전달, 규칙을 코드로 관리, 브라우저 자동 저장 | 동시 편집 불가 → JSON 합치기 / CSV 로 취합 |

"단순하고 직관적"이라는 요구에는 **더블클릭하면 열리는 파일 하나**가 가장 가깝다.
기준값은 코드가 아니라 설정 화면에 있어, 규칙이 바뀌면 설정만 고친다.

### Teams 공동 편집 — 산출물을 둘로 나눈 이유

**동시 편집은 확정된 요건이다.** 취합 담당자를 둘 수 없고, 모든 구성원이 각자 자기 근태를
직접 넣고 저장해야 한다. HTML 파일은 Office 문서가 아니라 SharePoint 공동 편집 대상이
아니므로, 이 요건을 HTML만으로는 충족할 수 없다.

그래서 산출물을 둘로 나눴다.

| 산출물 | 위치 | 역할 |
|---|---|---|
| `위례_근태관리.xlsx` | Teams (SharePoint) | **함께** — 모든 구성원이 동시에 자기 행 편집, 날짜별 30% 판정 자동 계산 |
| `index.html` | 각자 PC | **혼자** — 시각 단위 규칙 검증, 개인 총량·OT 잔여, 탄력근무 52/64 |

### 드롭다운이 곧 규칙 엔진이다

첫 시도에서는 엑셀에 **유형만** 드롭다운으로 넣었다. 그 결과는 현행 수기 관리에 집계만
붙인 수준이어서, 사용자가 "엑셀에는 HTML 만큼의 기능과 편리함이 없다"고 지적했다. 맞는
지적이었고, §5 의 성질을 제대로 쓰지 않은 탓이었다.

**규칙을 통과하는 근무 조합은 106가지뿐이다.** 그 목록을 `gen_combos.js` 가 HTML 의 규칙
엔진에서 직접 뽑아 계산의 원천으로 쓴다. 각 조합의 실근로 · 휴가 · 30% 충족이 표에 있으므로
나머지는 **조회만 하면 된다.**

처음에는 106가지를 **한 드롭다운**에 넣었는데, 사용자가 "고르기가 쉽지 않다"고 지적했다.
맞는 지적이라 입력을 세 칸으로 쪼갰다.

| 칸 | 항목 수 |
|---|---|
| 유형 | 11 (근무 · 오전반 · 오후반 · 오전반반 · 오후반반 · 검진 · 연차 · 출장 · 교육 · 기타 · 휴직) |
| 출근 | 6 (07:30 · 08:00 · 08:30 · 10:30 · 13:00 · 13:30) |
| 퇴근 | 18 (11:30 ~ 20:30) |

106가지 조합의 **시작 시각은 6가지, 종료 시각은 18가지밖에 없다** — 조합이 많아 보였을 뿐
축은 짧았다. 세 칸을 `유형 + 출근-퇴근` 문자열로 합쳐 조합표에서 찾고, 없으면 규칙 위반이므로
빨갛게 표시한다. 입력 단계에서 완전히 차단하지는 못하지만(세 칸이 독립적이라), 잘못된 조합은
즉시 눈에 띄고 실근로가 0으로 잡혀 집계에서 드러난다.

```
gen_combos.js  ─ HTML 규칙 엔진 ─→  combos.json (106가지)
                                        │
                                        ▼  build_xlsx.py
   근태 시트   빈칸 = 8시간 근무 · 하루 3칸 (유형 11 / 출근 6 / 퇴근 18)
      │
      ├─ 시간 시트   코드 → 실근로시간 (INDEX/MATCH)
      │
      ├─ 30% 판정    8시간 인원 = 활성 중 빈칸 + 충족 코드 수
      │              미달일은 빨갛게 · 조율 후보는 노랗게
      │              (출장 · 교육 · 연차는 바꿀 수 없으므로 후보에서 제외)
      │
      └─ 개인요약    조정 총량 = 소정 − 휴가 · 실근로 · OT 한도 = 기본 + 휴가
                     주별 근로시간(정규 + OT) 64h 판정
```

엑셀과 HTML 이 **같은 규칙 엔진을 원천으로 쓰므로** 두 판정이 어긋날 수 없다.
규칙을 고치면 `build_xlsx.py` 를 다시 돌려 엑셀을 새로 만든다.

### 세 번째 산출물 — Power Apps

사내 VDI 에서 Power Apps 생성 권한 · 라이선스 · 네트워크가 모두 확인되었고(2026-09),
SharePoint 목록과 Dataverse for Teams 두 경로 다 열려 있다.

Power Apps 가 엑셀보다 결정적으로 나은 지점은 **연쇄 드롭다운**이다. 엑셀에서는 유형 ·
출근 · 퇴근 세 칸이 서로를 몰라 불가능한 조합을 넣을 수 있고 사후에 빨갛게 표시할 수밖에
없지만, Power Apps 는 앞 칸의 선택으로 뒤 칸을 걸러낸다.

| 고른 것 | 다음 칸에 남는 항목 |
|---|---|
| 오전반 | 출근 **2개** → 퇴근 **4개** |
| 오후반반 | 출근 2개 → 퇴근 **1개** |
| 근무 | 출근 3개 → 퇴근 18개 |

한 번에 보이는 최대가 18개이고 대부분 1~5개다. 무엇보다 **규칙에 없는 조합은 목록에
나타나지 않으므로 고를 수 없다** — 엑셀의 "사후 표시"가 "원천 차단"이 된다.

구축 가이드는 [`POWERAPPS.md`](POWERAPPS.md) 에 있다. 세 산출물 모두 `combos.json` 을
원천으로 쓰므로 규칙을 한 곳에서 고치면 셋 다 갱신된다.

HTML 도구에만 남는 것은 **달을 넘기는 계산**(탄력근무 3개월 평균 52시간)과
**목록에 없는 조합이 왜 안 되는지 설명**하는 검증기다.

### 공휴일 자동 업데이트

완전 자동은 불가능하다. 설날 · 추석 · 부처님오신날은 **음력**이라 계산에 음력 변환표가
필요하고, 공공데이터포털 「특일정보」 API 는 **인터넷과 인증키**를 요구해 오프라인 파일
원칙과 충돌한다(사내망 허용 여부도 확인이 필요하다).

대신 설정 화면에 **「연도 추가」 버튼**을 넣었다. 양력 고정 공휴일과 **대체공휴일을 자동
계산**하고 회사 창립기념일(10월 13일)도 함께 넣는다(2027 · 2028년 결과를 요일까지 검증했다).
음력 3개만 매년 초에 한 번 직접 넣으면 된다.

## 8. 검증

전달받은 운영 사례를 **가능·불가능 양쪽 모두** 회귀 케이스로 고정했다. 도구의
「규칙 · 검증기」 탭에서 언제든 실행할 수 있고, 기준값을 바꾼 뒤 여기가 전부 통과하는지로
의도한 변경인지 확인한다.

- 근무 조합 38건 (실근로 시간 · 사용 가부 · 30% 충족 · 휴가 블록 위치 · OT 시간)
- 30% 필수 인원 올림 5건 (30 → 9 · 25 → 8 · 23 → 7 · 17 → 6 · 16 → 5)
- 총 **90개 단정** 전부 일치

규칙 C · D 는 검증기를 30분 격자 전체에 돌려 "사용 가능"으로 나온 조합을 눈으로 훑다가
발견했고, 규칙 E · F · G 는 그 목록을 사용자에게 보여 확인받는 과정에서 나왔다.
목록으로만 판정했다면 드러나지 않았을 결함이다. **격자 전체를 돌려 유효 조합을 눈으로
확인하는 절차**를 규칙을 바꿀 때마다 반복한다.

## 11. 확정된 사항

2026-09 확인 완료. 도구에 모두 반영되어 있다.

| 항목 | 확정 내용 |
|---|---|
| 30% 모수 | **팀장 2명 포함** — 명부 24명 − 휴직 1명 = 23명 → 필요 7명 |
| 판정 단위 | **전체 합산** (두 팀 기준) — 사규상 문제 없음. 그룹은 보기·관리 단위로만 |

| 반차 배치 | 오전 반차는 **점심까지** (`08:00~13:00` · `08:30~13:30`) 후 13:00 / 13:30 출근. `07:30~11:30` 은 불가 |
| 휴게시간 | 근무로 인정하지 않으므로 **그 안에서 시작·종료 불가** |
| 반반차 | 정규 근로시간(08:30~17:30) 앞뒤 2시간 **고정** — 출근 시각과 무관 |
| 월 총량 | 휴가를 쓰면 **그만큼 줄어든다** (160h − 연차 8h = 152h) |
| OT 한도 | **기본 가능시간 + 휴가 사용시간** (1일 휴가 → +8시간) |
| OT 시각 | **분 단위** · 자정을 넘겨도 됨 · 야간 가산은 급여 시스템 소관 |
| 석식 휴게 | **정규 종료 직후 30분**, 실시한 경우에만 공제. 근무·OT 모두 입력자가 선택 |
| 탄력근무 정규 | 단위기간마다 지정, **전 사업소 동일** |
| 휴일 근무 | 모든 날 가능, **가산 없이 근로시간만** 계산 |

## 12. 추가 제안

1. **승인 상태 관리** — 전월 말 계획에 대한 파트장·팀장 승인 여부를 기록해, 승인 없이 확정된
   계획을 구분한다. 30% 미달을 팀장 재량으로 승인한 날도 근거로 남는다.
2. **계획 / 실적 2계층** — 지금은 한 계층이다. 사전 승인받은 계획과 실제 실적을 나누면
   차이가 큰 날을 찾을 수 있다.
3. **8시간 부담 형평성** — 누가 월에 몇 일 8시간을 맡았는지 집계. 조율할 때 형평성 근거가 된다.
4. **선택근로 기간의 주 52시간 사전 경고** — 지금은 탄력 기간에만 판정한다. 선택근로에서도
   OT를 몰아 쓰면 주 단위 한도에 걸릴 수 있다.
5. **연차 잔여 연동** — 반차·반반차·연차 사용분을 합산해 잔여 연차를 함께 보여준다.
