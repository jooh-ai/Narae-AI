# 시운전 절차 — 새 테스트 실적으로 예측 정확도 검증

누적은 2026-04-02(31건)까지 반영돼 있고, 담당자로부터 2026-07까지 6건을 받은 상태를
전제로 한다. 이 6건은 **모델이 한 번도 본 적 없는 데이터**다. 그래서 지금이 예측
정확도를 제대로 측정할 수 있는 거의 유일한 기회다.

관련 문서: 첫 설치·RiMS 결선은 `ONSITE_TEST.md`, 배포·트러블슈팅은 `DEPLOY.md`.

---

## 0. 절대 규칙 — 예측을 먼저, 반영을 나중에

6건을 먼저 DB 에 넣고 나서 맞춰보면 **모델이 이미 그 값을 본 상태**다. 자기 데이터로
자기를 채점하는 셈이라 항상 좋게 나오고, 그 숫자는 실입찰에서 재현되지 않는다.

그래서 회차마다 이 순서를 지킨다. 순서를 어기면 그 회차는 폐기하고 다시 해야 한다.

```
예측 기록  →  실측 대조  →  반영  →  다음 회차
```

`scripts/commission.py` 가 이 순서를 강제한다. 예측은 항상 "반영 전 누적"으로 계산하고,
반영하는 순간의 예측값을 `commission_log.csv` 에 함께 적는다. 그 파일이 시운전 결과
보고서가 된다.

---

## 1. 섞으면 안 되는 세 가지

| 검증 | 무엇을 보는가 | 판정 | 언제 |
|---|---|---|---|
| ① 취득 일치 | RiMS 취득값이 담당자 표와 같은가 | 소수 4자리 | 반영 전 |
| ② 계산 일치 | 같은 입력에 같은 이론기준값·보정값이 나오는가 | ±0.25 MW | 반영 전 |
| ③ 예측 정확도 | 미리 낸 신고값이 실측과 맞는가 | ±0.5%(약 ±2 MW) | **반영 전만** |

①②는 결정론적 검사다 — 틀리면 버그이고, 값이 언제 확인되든 결과가 같다.
③만 순서에 민감하다. ①②가 통과하지 않은 건은 ③을 볼 의미가 없으니 먼저 잡는다.

> 참고: 실제 입찰은 **전날 예보 온도**로 낸다. 이 절차는 **실측 CIT**로 평가하므로
> 보정모델의 정확도만 본다. 예보 오차는 별개 항목이고, 섞으면 어느 쪽이 원인인지
> 구분할 수 없다.

## 2. 준비

**① 현재 상태 백업** — 되돌릴 수 있어야 마음 편히 진행한다.

```powershell
cd dist\WiryeBidTool          # 또는 tool 폴더(소스 실행 시)
copy wirye_measurements.db wirye_measurements_31건_백업.db
python -m wirye_capacity list | Select-Object -Last 5
```

기준선 확인: **31건, 마지막 2026-04-02**. 다르면 여기서 멈추고 원인을 먼저 확인한다.

**② 입력 서식 만들기**

```powershell
python scripts\commission.py --init
```

`commission_input.csv` 가 생긴다. 엑셀로 열어 담당자 표에서 6건을 옮겨 적는다.

| 열 | 내용 |
|---|---|
| `date` | 테스트 날짜 `YYYY-MM-DD` |
| `cit` | Comp. Inlet Temp (°C) |
| `press` | 대기압 (mbar) — Comp. Inlet Pres. 가 아니다 |
| `rh` | 상대습도 (%) |
| `cc_gross` | **CC(Gross)** 실측 (MW) — IGV 반영값 |
| `vac` | 진공도 (mbar), 없으면 비움 |
| `w` | W(IGV). 비우면 온도밴드 기본값(+6/+4/+2/0). **IGV Turn-up 미실시면 반드시 `0`** |
| `ref_theory` | 담당자 표의 이론기준값 → ② 검증에 쓴다 |
| `ref_corr` | 담당자 표의 보정값 → ② 검증에 쓴다 |

`ref_theory`·`ref_corr` 를 꼭 넣는다. 이게 없으면 ② 계산 일치를 건너뛰고, 나중에
차이가 났을 때 취득·계산·모델 중 무엇이 원인인지 못 가린다.

### ⚠ IGV Turn-up 실시 여부를 먼저 확인한다

보정값 = `CC실측 − 이론기준값 − W(IGV)` 다. **실시하지 않은 turn-up 을 빼면 보정값이
4~6 MW 낮게 기록된다.** 2026-08 시운전에서 8건 중 3건이 미실시였고, 그 3건이 전부
미달로 나와 모델이 틀린 것처럼 보였다. `w=0` 으로 바로잡자 잔차가 −6.3 → −1.7 MW 로
들어왔다.

- 미실시 회차는 입력 CSV 의 `w` 열에 **`0`** 을 적는다.
- 툴로 직접 취득할 때는 산정 탭의 **`IGV Turn-up 실시`** 체크를 해제한다
  (CLI 는 `--no-igv`). 기본은 실시(체크)다.
- 이미 잘못 넣었으면 [Test 결과 List-up] 에서 W 열을 편집한다.

**③ 전체 미리보기 (원본 안 바뀜)**

```powershell
python scripts\commission.py --walk
```

사본 DB 로 6회차를 순서대로 다 돌려 종합 판정까지 보여 준다. 여기서 이상한 건이
보이면(계산 일치 ❌, 미달, RH 이상치) 실제 반영 전에 담당자와 먼저 확인한다.

## 3. 회차 절차 (6회 반복)

### STEP 1 — 취득 일치 확인 (RiMS 접속 가능할 때만)

툴이 그 날짜를 직접 취득해 담당자 표와 같은지 본다. 이걸 먼저 하는 이유는, CC실측이
1 MW 틀리면 보정값이 그대로 1 MW 틀리기 때문이다.

```powershell
python -m wirye_capacity check-rims --date 2026-05-12 --start 15:00
```

취득 시각이 표의 **`Data 취득 시작~종료 시간`** 과 같아야 한다(대부분 15:00 또는 16:00
시작 1시간). 다르면 값이 달라진다.

여러 건을 한 번에 보려면:

```powershell
python scripts\source_compare.py --date 2026-05-12 --start 15:00
```

**판정**: CIT·대기압·RH·CC 가 소수 4자리까지 일치 → 통과. 어긋나면 `--start` 를 표와
맞춰 다시 확인하고, 그래도 다르면 담당자와 수식(fnTagStat vs eDNA)을 확인한다.
2025-10-28 이 그런 사례였다.

### STEP 2 — 예측·대조 (DB 안 바꿈)

```powershell
python scripts\commission.py --step
```

가장 이른 미반영 건 1개를 잡아 ①② 검증과 세 방법의 예측을 한 화면에 보여 준다.

```
② 예측 정확도 (반영 전 예측 vs 실측)
   실측 신고값(Net) 418.90 MW    허용밴드 ±0.5%
   방법             예측 보정    예측 Net     실측-예측  판정
   구간평균          +2.619    418.39     +0.51  ✅ 밴드 내
   커널회귀          +3.529    419.30     -0.40  ✅ 밴드 내
   GP            +3.105    418.88     +0.02  ✅ 밴드 내
```

### STEP 3 — 판정

| 표시 | 뜻 | 조치 |
|---|---|---|
| ✅ 밴드 내 | \|실측−예측\| ≤ 0.5% | 통과 |
| 밴드 위(안전) | 실측이 예측보다 높음 | 통과. 기회손실이지만 페널티 없음 |
| ⚠ 미달 | 실측 < 예측−0.5% | **문제.** 신고량을 못 지킨 경우다 |
| ❌ 계산 일치 | 표와 0.25 MW 초과 차이 | **반영하지 말고** 원인부터 |

`이 구간 실측 N건뿐` 같은 안내가 나오면 그 구간 근거가 얇다는 뜻이니 함께 적어 둔다.

### STEP 4 — 반영

판정이 납득되면 반영한다. 이때 그 회차의 예측값이 기록에 남는다.

```powershell
python scripts\commission.py --step --apply
```

### STEP 5 — 다음 회차

STEP 1 로 돌아간다. 6회를 마치면 남은 회차 0으로 표시된다.

## 4. 종합 판정

```powershell
python scripts\commission.py --walk      # 백업 DB 로 돌리면 전 회차 종합 판정
python scripts\commission.py --report    # 회차 기록 원본(CSV)
```

```
방법              평균오차      최대오차     밴드 내     미달
구간평균           1.462     2.644      3/6     1건
커널회귀           0.904     1.624      6/6     0건
GP             0.938     2.518      4/6     0건
```

**판정 기준은 미달 0건이 최우선**이고, 그 다음이 평균오차다. 미달은 페널티로 이어지고
밴드 위는 기회손실에 그치므로 두 오차의 무게가 다르다.

이걸로 결정할 것 두 가지.

1. **보정 방법 확정** — 6건에서 가장 나은 쪽으로 고정한다. 화면에서 고르면 저장되어
   다음 실행에도 유지된다. 구간평균은 담당자 실적표와 계산이 같아 소명이 쉬운 장점이
   따로 있으니, 오차 차이가 0.1 MW 수준이면 그 점도 함께 본다.
2. **안전마진 필요 여부** — 미달이 한 건이라도 있으면 `안전마진 계수 0.8` 을 켜고
   `--walk` 를 다시 돌려 미달이 0이 되는지 확인한다. 마진은 오차를 키우는 대신 전부
   안전한 방향으로 밀어낸다.

6건은 표본이 작다. 실입찰 전환 판단은 병행운전(`ONSITE_TEST.md` STEP 6)을 2~3회 더
거친 뒤에 한다.

## 5. 이번 6건에서 특별히 볼 것

**여름 데이터의 1년 경과.** 받은 6건은 2026-04~07 이고, 누적의 여름 데이터는 전부
2025-07~09 다. 30~41°C 구간은 지금 2025년 여름 실적만으로 채워져 있어, 이번 건들이
**1년 뒤 같은 설비가 같은 수준인지**를 처음으로 검증한다.

이미 비슷한 일이 한 번 있었다. 2025 상반기 실적은 하반기 이후보다 보정값이 4 MW 낮아
별개 시기로 판단하고 제외했다(`scripts/period_check.py`). 그래서 이번에도 같은 것을
본다.

- 6건이 **한 방향으로 치우쳐** 낮게 나오면 → 시기 차이(열화 또는 정비 이력) 신호다.
  개별 이상치가 아니므로 곡선을 그냥 끌어내리면 안 되고, 정비 이력을 확인해
  "그 시점 이후만 사용" 규칙을 검토한다.
- **흩어져서** 어긋나면 → 예측 오차 범위 문제다. 표본을 더 쌓거나 안전마진으로 대응한다.

반영 후에 시기 효과를 다시 보려면:

```powershell
python scripts\method_compare.py     # 날짜순 walk-forward 포함
```
